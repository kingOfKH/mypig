数据迁移

换服务器时不再需要手工搬运整个目录：老服务器一键导出全部运行时数据，新服务器只需 git clone 项目代码，再在这里上传迁移包即可完整接管。

1
老服务器 · 导出
建议在夜间低峰操作，导出期间避免写入
2
新服务器 · 拉取源码
git clone 后 npm install，代码与静态资源随仓库同步
3
新服务器 · 导入
上传 zip，自动备份后整包覆盖，重启服务生效
↓

导出数据

打包全部运行时数据为 zip

导出包含服务运行所需的全部数据，不含源码，新服务器只需拉取仓库代码；导出包只下载到本机，服务端不留存副本：

  • data/ 设备档案、信任关系、积分、聊天/快照/头像/剪贴板、表情配置、TLS 证书与后台登录密钥
  • updates/ 已发布的 APK 与版本元数据
  • public/emoji/custom/ 用户上传的自定义表情图片
  • .env* 环境变量与后台账号配置
  • 不含 *.js、*.html、node_modules/、.git/、backups/
↑

迁入数据

上传迁移包并覆盖本机数据
覆盖导入：本机现有的 data/、updates/、自定义表情与 .env* 会先被清空，完全以老服务器的包为准。导入前会自动把本机现状备份到 backups/。

服务端留存包

导出包不落盘，无需清理；这里只列出「导入前自动备份」（每次迁入自动替换上一份，只保留最新）与异常残留的上传临时文件
正在加载…

备份包含全部密钥与证书，建议定期下载归档；导入前备份由服务端自动轮转，页面只提供查看与下载。

正在处理，请勿关闭页面…

迁移包内含密钥与证书，请妥善保管、勿通过公开渠道传输。导入后建议重启服务端进程，以刷新 dotenv、TLS 证书、后台登录签名密钥等启动时读取的状态；重启后请使用老服务器的后台账号密码重新登录。
若导出或导入因数据量过大失败（单包上限 2GB），可先到「资产管理」清理历史快照/聊天图片，或手工搬运目录。
